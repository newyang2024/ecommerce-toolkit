营销日历工具便携版迁移说明
========================

一、这份压缩包是什么

压缩包内含当前工具代码、Python 3.10.11 x64 完整运行时（包括 Tkinter/Tcl/Tk）、
Playwright 1.63.0 及其本机已验证的依赖、测试和示例配置。解压后运行工具，
目标电脑不需要另行安装 Python，也不需要在目标电脑运行 pip。
请查看包内“版本信息.txt”确认源码提交和打包版本。

这是“带运行时的便携版”，不是脱离操作系统的单个 exe。它只适用于 64 位 Windows。
包内没有日报表底本、下载报表、账号、Cookie、登录态、浏览器配置、本机路径配置
或历史运行结果。

二、新电脑仍需具备什么

1. 已安装 Microsoft Edge，能够直接访问 one.alimama.com。
2. 已安装桌面版 Microsoft Excel；完整数据整理后的透视表刷新依赖 Excel 的
   Windows COM 功能。仅有 WPS、网页版 Excel 或未安装 Excel，不能保证完整流程。
3. 有权使用万相台报表的账号；登录和滑块等安全验证必须本人手动完成。
4. 一份业务正确的“日报表底本.xlsx”：其中应有最新“匹配源”、足够的公式行
   和原有汇总透视表。此文件须通过私有可信方式单独转移，不能上传公开仓库。
5. 解压位置有足够剩余磁盘空间和读写权限。大型 Excel 输出可能占用较多空间。

三、收到文件后先验包

包旁边有同名的 .sha256.txt 文件，记录 ZIP 的 SHA-256。若两者一起传输，
可在 PowerShell 中执行：

    Get-FileHash -Algorithm SHA256 "实际压缩包路径.zip"

将输出的 Hash 与 .sha256.txt 中的 64 位字符比对；不同则不要运行，
请重新传输。只从可信来源取得压缩包，不要运行来源不明的替换版本。

四、解压和首次检查

1. 将 ZIP 完整解压到本机普通文件夹，例如 D:\MarketingCalendar\。
   不要直接在压缩包预览窗口中双击启动，不要只复制启动 .bat 而漏掉 runtime。
2. 解压后确认同一文件夹下能看到：
   main.py、启动营销日历工具.bat、runtime\python.exe、
   runtime\pythonw.exe、marketing_calendar\、config\。
3. 在该文件夹打开 PowerShell，运行：

    .\runtime\python.exe main.py check

   应看到“配置检查通过”和 Playwright 1.63.0。这个命令不登录、不创建下载任务。
4. 如需做本机运行时自检，可运行：

    .\runtime\python.exe -m unittest discover -s tests -q

   测试只检查代码逻辑，不连接网站。
5. 可直接双击“启动营销日历工具.bat”打开图形工作台；也可运行：

    .\runtime\python.exe main.py gui

   启动脚本优先使用包内 runtime，不依赖系统 PATH 中的 Python。

五、第一次实际使用

1. 在工作台点击“打开登录浏览器”，等待项目专用 Edge 出现。
2. 在 Edge 中自行登录万相台并完成网站要求的安全验证；不要在普通 Edge
   与项目专用 Edge 之间混淆登录状态。
3. 回到工作台，核对“开始日期”“结束日期”。默认规则是上月 1 日至昨天；
   若网站数据尚未更新到昨天，请以实际可用的最新日期调整。
4. 在“日报表底本”选择已经单独转移的 .xlsx 文件。底本只读使用，
   程序会生成新结果，不应改写底本。
5. 选择输出目录，然后开始五表流程。流程是先依次提交并确认五张报表任务，
   再统一进入下载任务管理页下载、解压、校验，最后整理 Excel。
6. 完成后在输出目录查看本次运行文件夹。核对五份 CSV 的报表类型、日期和列，
   再核对新 Excel 中的主体源、人群源、词源、匹配源和汇总透视表；
   型号、类目等业务映射应按权威资料人工核对。

六、原电脑哪些东西要单独迁移

必须单独迁移：最新且已核对的日报表底本。请确保新电脑选中的是这一份，
特别检查“匹配源”末尾新增记录是否存在。

通常不迁移：data\browser_profile、browser_session.json、Cookie、
账号或密码。新电脑的登录态需要重新建立。

可选迁移：output\ 里的历史 ZIP、CSV、运行清单和 Excel，仅在需要留档、
复查或离线处理时复制。历史运行目录包含业务数据，应单独保管；
复制时保持整个运行目录的结构，不能只挑出一个 manifest.json。

不要把真实底本、输出、日志、浏览器配置、密钥或账号信息提交到 GitHub。

七、配置和路径

默认 output\、logs\、data\browser_profile\ 都在解压目录内，
不依赖原电脑的用户名、盘符或固定 IP。图形界面的输出目录可直接修改。
普通迁移不需要创建 config\config.json。

命令行如需自定义路径，可以复制 config\config.example.json 为
config\config.json，并在具体命令后传入：

    .\runtime\python.exe main.py check --config config\config.json

注意：当前图形入口使用默认配置，不会自动读取这个自定义 config.json；
不要以为修改它就会改变工作台的浏览器配置。不要在配置中添加代理地址。
程序联网遵守直连原则，不使用系统或环境代理。

八、常见问题及处理

双击后一闪而过：
  用 PowerShell 执行“.\runtime\python.exe main.py gui”查看错误；
  同时检查 logs\gui_startup_error.log。确认已完整解压 runtime 文件夹。

提示没有 Edge：
  在新电脑安装 Microsoft Edge，重新打开工具；不要复制原电脑浏览器目录。

提示未登录或出现滑块：
  回项目专用 Edge 手动登录或完成验证，再回工作台按提示继续。
  提交结果不明确时先核对网站下载任务，不能盲目重新提交。

下载页暂停：
  已确认任务短暂未出现在列表时，程序会只读重查；若仍找不到，
  请先在网站核对任务 ID 和状态。不要连续点击“开始”新建同日期任务。
  在工作台选择“继续当前任务”会沿用原运行记录。

提示缺少 Excel 或透视表刷新失败：
  确认安装并能打开桌面版 Microsoft Excel，再关闭占用中的工作簿重试。
  仅用 WPS 查看结果不等于已完成 Excel 原生透视表刷新。

提示底本公式行不足、列不匹配或映射出现 N/A、0：
  停止发布结果；检查底本公式行、五份 CSV 维度列及匹配源的主体 ID、
  货号、简称、类目。不要让程序凭标题猜测业务型号。

九、代码更新与维护

这份 ZIP 是某次源码快照，不会自动跟随 GitHub 更新。后续开发的唯一代码来源是：
https://github.com/newyang2024/ecommerce-toolkit

维护代码请使用该仓库的 marketing-calendar 目录；不要在解压后的便携包里
长期做代码改动。升级时先保留旧包和业务数据，再取得新包；不要用新包
直接覆盖包含 output 或 browser_profile 的旧目录，避免丢失运行记录。
如需在 Codex 中维护，请把本地克隆的 ecommerce-toolkit 文件夹设为项目；
便携包只用于运行和迁移。

十、边界说明

包内 Python 与依赖来自打包电脑上已验证的安装，不会在目标电脑下载依赖。
打包脚本本身不访问网络。迁移后是否能完整运行，还取决于新电脑的 Edge、
Excel、网站权限、网络直连、底本质量和 Windows 系统环境。
出现无法复现的暂停时，请保存错误提示、运行目录名、日志和对应页面截图
供排查，但不要公开包含账号或业务数据的原文件。
