# 模块经验沉淀：05 真机探查商品页结构

## 1. 模块目标

在已登录的真实 Edge 上打开商品页，摸清媒体区、缩略图、视频、SKU 的真实 DOM 结构，确认营销主图怎么定位、高清图怎么获取，产出页面控件清单，为后续定位和识别提供依据。

## 2. 实际产出

- 页面控件清单_真机探查.md：完整记录布局、选择器、营销图定位、高清图 URL 规律、视频和 SKU 处理
- 确认营销主图就是第一张缩略图，文件名都含 picasso.jpg
- 验证了美的、海尔 6 个商品，含视频商品和多颜色价格商品，规律通用
- 下载并核对了 7 张真实图片，确认各图内容

## 3. 遇到的问题

- 探查脚本运行时间较长，超过前台等待被转到后台，需要轮询等结果。
- 缩略图末尾有 2 到 3 个空占位，一开始以为是图片没加载，实际是占位项。

## 4. 踩过的坑

- 类名带哈希后缀（如 mainPic--zxTtQs0P），不能写死，要用前缀包含匹配。
- 下载的高清图是 webp 格式，查看时要确认工具能读。

## 5. 原本以为 vs 实际发现

- 以为营销主图要点击翻找，实际第一张缩略图就是，而且规律非常稳定。
- 以为有视频的商品营销图位置会不同，实际视频封面就是营销图，仍在第一张。
- 以为要靠点击切换才能拿到各图，实际直接从缩略图 URL 就能构造高清图下载，完全不用交互。
- 实际看到海尔 617 确实按灰色 4899、白色 4999 分别标价，验证了多颜色价格场景真实存在。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- image_locator 直接依赖第一张 picasso 图的定位和 URL 构造，若天猫改版改命名，需要回这里更新。
- 前缀包含匹配是关键，若天猫把类名前缀也改了，定位会失效，要在冒烟时重点验证。
- 第二张图是权益信息的补充来源，若第一张权益识别不全，可启用第二张。
- 不同商品缩略图数量略有差异（8 或 9），定位第一张不受影响，但不要依赖固定总数。
- 高清图下载走 alicdn，若网络或代理拦截图片域名，需要回退到截图方案。
