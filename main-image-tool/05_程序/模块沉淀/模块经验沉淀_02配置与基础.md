# 模块经验沉淀：02 配置与基础

## 1. 模块目标

写好运行配置和字段规则的初版，提供配置加载和按天滚动日志两个基础能力，让后续模块统一从配置读参数，不写死在代码里。

## 2. 实际产出

- config/config.yaml：浏览器、采集、拟人延迟、路径、输出五组运行参数
- config/rules.yaml：颜色映射、价格、时间、权益四分层的关键词和正则
- core/config_loader.py：加载两个 YAML，提供相对路径解析
- core/logger.py：控制台加按天滚动文件日志
- core/__init__.py：包初始化
- 验证：两个配置加载成功，路径解析正确，链接库文件存在，日志成功写入 06_结果输出/日志/run_20261029.log

## 3. 遇到的问题

- logger 初版把一个回退路径的 import 写在了文件末尾，前向引用顺序不对，重写后理顺了 import 位置。

## 4. 踩过的坑

- 相对路径解析要统一以程序根目录为基准，不能依赖运行时的当前目录，否则从别的目录启动就找不到文件。

## 5. 原本以为 vs 实际发现

- 以为正则写在 YAML 里会被直接当字符串用，实际要分清引号：单引号字符串里反斜杠是字面量，正则写单反斜杠（'\d'）即可；双引号字符串里反斜杠是转义符，才需要写双反斜杠。本项目规则统一用单引号，写单反斜杠。
- 以为日志目录要单独建，实际在 logger 里自动创建更省心，配置取不到时还回退到程序根目录下的 logs。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 浏览器、采集、输出模块都会引用 config，改配置字段名会直接让下游报错，新增字段可以，重命名要同步改代码。
- 权益和颜色的关键词全部在 rules.yaml，后续真机识别发现新写法时只改配置，这是设计好的扩展点。
- 颜色待确认项（山海米、烟青色、云雾岩）先列在 rules 的 pending 里，等用户拍板后再归并。
- 时间正则目前是基础版，真机上出现“晚 8 点”“零点”等写法时可能要补充。
