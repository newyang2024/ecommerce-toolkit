# 模块经验沉淀 前端06 复核清单标签页

## 1. 模块目标
把人工复核清单在"复核清单"标签页里结构化展示，让用户清楚看到每个待复核商品的字段、原因和当前值，能按原因类型筛选，并且能直接打开原始 Markdown。只展示、不编辑，符合之前确认的复核口径。

## 2. 实际产出
- state_reader 增加 parse_review_items：解析复核清单，返回完整条目（序号、名称、item_id、字段、问题、详情）。
- 重写 ui/review_tab.py：筛选下拉、复核表格（序号、商品、字段、复核原因、当前值/详情）、刷新和打开 Markdown 按钮。
- main_window 在采集正常结束后同时刷新复核清单。
- 真机验证：13 项全部展示，原因分布（9 个价格无法唯一确定、3 个含推断、1 个标签对不上），筛选"含推断"正确显示 3 项且保留原序号。

## 3. 遇到的问题
- 复核清单的详情里有 Python 字典字符串（如标签价 {'白': '2899'}），要原样保留，不能误解析或转义。

## 4. 踩过的坑
- 筛选后表格里的序号要保留清单里的原始序号，不能重新编号，否则用户对照导出文件时会错位。
- 筛选下拉的选项要根据当前清单动态生成，写死会在原因类型变化时失效。
- 重建下拉时要 blockSignals，否则清空和添加会触发多次筛选刷新。

## 5. 原本以为 vs 实际发现
- 原本以为复核清单要单独写一套解析，实际模块5已经有定位和基础解析，本模块只补了完整条目解析。
- 原本以为原因类型很多，实际当前清单全部集中在主图价格字段，分三类原因。

## 6. 下游引用及后续开发可能影响该模块的风险检点
- 模块7联调时要确认采集后复核清单和结果表格的状态对得上（待复核、待确认数量一致）。
- 以后 review.py 如果新增字段或原因类型（比如时间、权益复核），parse_review_items 能通用，但筛选和列展示要确认是否需要调整。
- 活动开始后重跑，问号商品价格补全，复核清单条目数会明显减少，属正常。
- 打开 Markdown 依赖系统默认程序，个别电脑没有关联编辑器时可能打不开，可提示用户直接去结果目录找。
