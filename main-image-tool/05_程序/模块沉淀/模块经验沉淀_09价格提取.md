# 模块经验沉淀：09 价格提取

## 1. 模块目标

按确认口径提取价格：单一价格所有行直接填，不做颜色对应；多价格按颜色或门型的空间位置匹配；双色同价填同一价；匹配不到唯一价格时列候选并标记人工复核，不猜测。

## 2. 实际产出

- core/price_extractor.py：PriceResult 结构，候选价格收集、语境噪声排除、单多价格判断、空间匹配
- rules.yaml 价格部分：价格数字正则、连写价格正则、合理范围
- 真机验证：美的 631 单一价格 4349，海尔 617 灰 4899 白 4999
- 边界覆盖：连写不同价、无颜色标签、容量和满减干扰全部正确

## 3. 遇到的问题

- 连写不同价一开始两个价格都匹配到同一颜色，通过拆分左右半位置、改用综合距离解决。
- 测试辅助块把宽度写死成 1，导致连写位置拆分看不出效果，修正测试数据后正常。

## 4. 踩过的坑

- 连写的两个价格要各自估算中心，不能共用文字块中心。
- 颜色和价格配对不能只看纵向距离，同一行颜色要靠横向距离区分，用横向加纵向的综合距离最稳。
- 容量带 L、满减带“满、消费、使用”语境，要排除，避免误当价格。

## 5. 原本以为 vs 实际发现

- 以为颜色对应会很难，实际单一价格占多数，多价格靠空间位置也能稳定匹配。
- 以为满减数字会大量干扰，实际它们多是 3 位或带语境，纯 4 位价格块很干净。
- 真机上多价格的两个数字是独立块，连写不同价主要靠逻辑兜底。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 价格回填要按行的颜色组取 price_map，单一价格直接填全部行。
- 空间匹配阈值（横向 200、上方）是按真机图调的，不同分辨率或新布局可能要调，冒烟时验证。
- 门型多价格目前复用颜色逻辑，若真机出现按门型标价，要补充门型标签匹配。
- 匹配不到时列候选并标记，不能为了填数而猜测。
- 价格范围写死在 1000 到 99999，若有超低价小冰箱或高端机型，要核对范围。
