# 模块经验沉淀：10 权益提取

## 1. 模块目标

把权益归到赠品、保障权益、红包、其他四分层，保留原文，去重，不重复归类，支持第一张主图和第二张权益专图合并，拿不准的不乱归。

## 2. 实际产出

- core/benefit_extractor.py：四分层分类、噪声过滤、核心点归并
- rules.yaml benefit 部分：噪声词、赠品引导词、四类关键词
- 真机验证美的 631：赠品烤箱皮肤贴、制冰舱、汤锅，保障价保、压缩机包换、送货入户、保修，红包返50到200，其他补贴套购折扣
- 海尔 617：赠品文创礼包、托特包，保障价保、买贵、运费险、延保，红包瓜分和返现，其他补贴免息

## 3. 遇到的问题

- 初版引导语、单字块、价格计算式被当成权益，通过噪声过滤解决。
- 两张图同一权益不同说法造成重复，通过核心点归并解决。
- 折扣一度被过度合并，改成按具体折扣值区分。

## 4. 踩过的坑

- 噪声过滤不能一刀切，含“立即抢购”的块可能同时有“价保”，要先分类再过滤纯引导。
- 归并要按核心点，不同折扣值不能合并。
- “赠运费险”是保障不是赠品，保障要在赠品前判断。

## 5. 原本以为 vs 实际发现

- 以为权益归类会很乱，实际四类关键词覆盖得比较全，噪声过滤后结果清楚。
- 第二张权益专图确实更全，但会带来重复，需要归并。
- 单字块和纯标签块比预想的多，是主要噪声来源。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 核心点归并规则写在代码里，新权益类型要同步补充。
- 保留原文意味着文字可能较长，Excel 单元格要换行、列宽要够。
- 个别块可能同时含多个类别特征，当前按保障、赠品、红包、其他的优先级，冒烟时核对。
- 若新主图出现四类都不匹配的权益，会被跳过，冒烟时收集补充。
- 第二张图是否启用、如何合并，直接影响结果数量和重复程度。
