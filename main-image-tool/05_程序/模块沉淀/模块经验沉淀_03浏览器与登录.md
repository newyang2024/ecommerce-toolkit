# 模块经验沉淀：03 浏览器与登录

## 1. 模块目标

通过 CDP 连接手动登录的真实 Edge（端口 9223），注入反检测脚本，提供拟人延迟和新页面开关，并能准确判断天猫登录态，为后续采集打基础。

## 2. 实际产出

- core/browser.py：CDP 连接、端口探测、反检测注入、拟人延迟、新页面开关、断开连接
- core/login_check.py：结合 cookie 和页面控件判断登录态
- launch_edge.py：启动带调试端口的专用 Edge，独立配置与日常浏览器并存
- 真机验证：连接成功，登录态正确，真实商品页（美的 631 十字冰箱）正常打开，标题正确

## 3. 遇到的问题

- 真机连接报 socket hang up，本机代理拦截了本地端口连接，已通过强制绕过代理解决。
- 未登录时登录检查误判为已登录，修正为以 unb 为依据。
- 第一次测试用的商品 id 是被截断的无效链接，跳到了错误页，改用完整链接后正常。

## 4. 踩过的坑

- 绕过代理的代码必须在 import playwright 之前执行，写在后面不生效。
- 不能用随便拼的商品 id 测试，必须用链接库里的完整真实链接。

## 5. 原本以为 vs 实际发现

- 以为参考项目已经解决了代理问题，本项目不会再遇到，实际新代码库仍要重新实现一遍绕过逻辑。
- 以为 _tb_token_ 是登录后才有的令牌，实际未登录访问也会种下，真正代表登录的是 unb。
- 以为专用 Edge 启动后会自动带登录态，实际是全新配置，需要用户手动登录一次。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 所有采集都通过 BrowserManager 连接和开页面，连接逻辑或反检测改动会影响全部下游。
- 登录态有有效期，长时间运行可能失效，批量流程里要在关键节点复查登录态，失效时提示重新登录。
- 专用 Edge 配置保存在 05_程序/data/edge_cdp_profile，换机或迁移时该目录的登录态要重新建立。
- 端口 9223 与老项目 9222 隔离，若 9223 被占用或未启动，采集第一步就会失败。
- 反检测脚本只隐藏了常见特征，若天猫加强检测，可能需要补充，但本工具只读不交互，风险较低。

## 7. 待办

- 批量流程中接入登录态复查，失效时安全暂停并提示。
- 步骤 5 真机探查商品页时，确认媒体区在已登录状态下的真实结构。
- 后续评估是否写一个一键启动 Edge 的 bat，方便日常使用。
