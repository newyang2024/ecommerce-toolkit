# 模块经验沉淀：07 OCR 引擎

## 1. 模块目标

封装 RapidOCR，做成单例避免重复加载模型，输出统一的文字块结构，带文本、坐标、置信度和相对位置，并能保存原始 OCR 结果，供三个提取器使用。

## 2. 实际产出

- core/ocr_engine.py：TextBlock 数据结构、模型单例、OCREngine 识别和原始结果保存
- 真机验证：两张高清主图分别识别 60 和 73 个文字块，每张约 4 到 5 秒
- 低置信块很少，每张只有 2 到 3 个，位置字段正确
- 原始结果 JSON 已保存

## 3. 遇到的问题

- 本模块没有明显问题，模型加载和识别一次通过。

## 4. 踩过的坑

- 模型加载约 5 秒，必须做单例，否则每个商品重复加载会非常慢。
- 相对位置要除以图片真实宽高，不能用固定像素，不同图尺寸有差异。

## 5. 原本以为 vs 实际发现

- 担心 opencv 5.0 与 rapidocr 不兼容，实际识别全程无报错。
- 以为识别会有不少错字，实际置信度大多在 0.95 以上，价格、时间、权益都识别清楚。
- 发现双色同价的两个价格会连成一个字符串，如 43494349，要在价格提取时拆开。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 三个提取器全部基于 TextBlock，字段改动会影响下游。
- 每张图识别约 4 到 5 秒，47 个商品纯 OCR 就要 4 分钟左右，批量总时长要预留。
- 价格连写、竖排文字等情况需要在提取器里专门处理。
- 低置信块虽然少，但可能正好是关键信息，提取时要关注并标记。
- 原始结果 JSON 是后续核对和调参的依据，建议保留。
