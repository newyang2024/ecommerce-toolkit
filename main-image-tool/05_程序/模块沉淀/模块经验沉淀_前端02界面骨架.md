# 模块经验沉淀：前端02 界面骨架

## 1. 模块目标
搭出桌面应用的完整骨架，包括主窗口、顶部环境区、三个标签页和状态栏，配好统一的配色样式，再提供双击启动入口，让后续模块可以直接往骨架里填功能。

## 2. 实际产出
- ui/app_style.py：统一的配色和样式表，定义主色、按钮、标签页、分组框、输入框、进度条、表格、日志、滚动条等全套样式。
- ui/widgets.py：状态灯、状态项、统计卡片等通用小组件。
- ui/main_window.py：主窗口，顶部环境区含浏览器和登录状态、链接库信息、启动和检测按钮，中部三个标签页，底部状态栏。
- ui/collect_tab.py、result_tab.py、review_tab.py：三个标签页占位。
- start_app.py：桌面应用入口，含高分屏适配。
- 启动工具.bat：双击启动，异常时暂停显示错误。
- 真实平台截图验证：布局完整，文字和状态显示正常。

## 3. 遇到的问题
- main_window 里误用了 lib.rows，实际属性是 lib.items，已修正。
- offscreen 离屏平台在本机渲染不出文字，截图全是空白，改用真实平台启动并定时截图后正常。

## 4. 踩过的坑
- 不能用 offscreen 平台的截图来判断界面效果，这个环境的离屏渲染缺少字体支持，会误判成文字丢失。
- 真实平台验证 GUI 要用 QTimer 定时截图再退出，不能直接阻塞，否则脚本无法自动结束。
- 高分屏要在创建 QApplication 前设置 AA_EnableHighDpiScaling，否则界面会发虚。

## 5. 原本以为 vs 实际发现
- 以为 offscreen 能快速验证界面，实际它渲染不了文字，验证界面必须用真实平台。
- 实际搭出来后，样式表一次成型，真实平台的布局和预期一致，蓝色主色调清晰不刺眼。
- 链接库信息在窗口初始化时就能读到，加载很快，不需要额外做加载提示。

## 6. 下游引用及后续开发可能影响该模块的风险检点
- 三个标签页目前是占位，后续模块要替换成完整实现，注意保持标签页类名和主窗口的引用一致。
- 顶部"启动浏览器"和"重新检测"按钮目前没接逻辑，模块3要把它们和 browser_worker 连起来。
- 样式表是全局应用，后续模块新增控件时尽量复用已有的 objectName 和样式，避免每个控件单独写样式导致风格不统一。
- 启动工具.bat 里写死了 Python 路径，如果换机或 Python 位置变化，需要改路径或改用 PATH 里的 python。
- 主窗口初始化会读一次链接库，后续如果链接库被更换，需要提供刷新入口重新加载。
