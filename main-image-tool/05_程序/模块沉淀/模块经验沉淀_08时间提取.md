# 模块经验沉淀：08 时间提取

## 1. 模块目标

从 OCR 文字块识别活动时间，优先识别完整范围，单个时点如实记录，不臆测结束，处理跨月跨年、口语时点和省略月份，拿不准的标记人工复核。

## 2. 实际产出

- core/time_extractor.py：TimeResult 结构，五种时间形态匹配，活动时间标签优先
- rules.yaml 时间部分：完整范围、省略月范围、当天时段、日期范围、单个时点、晚时点六个正则
- 真机验证：海尔 617 完整范围识别为 10月30日20点 到 11月1日24点，美的 631 单时点识别为 10月30日20点
- 模拟覆盖：当天时段、日期范围、省略月范围、晚X点全部正确

## 3. 遇到的问题

- 初版所有时间都提取为空，根因是 YAML 单引号里正则写成了双反斜杠，已修。
- 晚X点一开始匹配不到，补了专门的 evening 模式并换算 24 小时。
- 编译正则时把 same_day 的键名写错，已对齐。

## 4. 踩过的坑

- 单引号 YAML 里反斜杠是字面量，正则写单反斜杠，不能写双反斜杠。
- 时间标签块要优先，图上可能有多个时间说法，以“活动时间”最规范。
- 晚8点要换算成20点，不能直接当8点。

## 5. 原本以为 vs 实际发现

- 以为时间主要是完整范围，实际真机上单个时点、当天时段、日期范围都有，要分别处理。
- 以为配置能加载正则就没问题，实际转义错了也能加载，只是匹配不到，必须用真实样例验证。
- 活动时间标签块非常可靠，优先找它能避开图上其他零散时间的干扰。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 省略月份的时间补的是当前月，若活动实际跨月或在次月，需要人工核对，已用 need_review 标记。
- 时间块可能有多个且说法不完全一致，最终取标签块，无标签时取第一个匹配，结果要保留原文便于核对。
- 真机上还可能出现“零点、整、截至”等新写法，冒烟时收集，补充正则。
- 跨年逻辑只在结束月小于开始月时触发，跨年活动要重点验证。
