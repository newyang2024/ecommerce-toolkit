# 模块经验沉淀：06 营销主图定位

## 1. 模块目标

写好 image_locator，在商品页定位营销主图，构造高清 URL 下载，同时下载第二张权益补充图，下载失败能回退截图，并系统梳理主图的信息布局和常出现位置。

## 2. 实际产出

- core/image_locator.py：定位第一张缩略图、构造高清 URL、下载、第二张补充、截图兜底
- 主图布局全局分析.md：三种模板的信息位置、各字段常出现位置、抓取逻辑
- 真机验证：3 个商品主图全部下载成功，均为高清版，第二张补充图也都拿到

## 3. 遇到的问题

- 配置里缺少 main_image_dir 路径，首次运行报 KeyError，补上路径后正常。
- 高清 URL 构造初版重复加了扩展名，变成 .jpg.jpg 或 .png.jpg，导致 404。

## 4. 踩过的坑

- 构造高清 URL 时，去掉压缩后缀后要先检查 base 是否已经带扩展名，不能盲目再补。
- 缩略图第 0 和第 1 个位置是重复的同一张图，要先去重，否则第二张补充图会取错。

## 5. 原本以为 vs 实际发现

- 以为高清图要复杂处理，实际规律很简单，去掉压缩后缀、保留原扩展名即可。
- 以为价格都在底部，实际模板二价格在左中，所以位置只能做辅助，不能只裁底部。
- 实际确认第二张图是权益专图，8 大权益列得比第一张更清楚，值得保留。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- OCR 和三个提取器都依赖下载的主图，图片清晰度直接影响识别准确率。
- 第二张图是权益补充，benefit_extractor 要支持读两张图合并结果。
- 高清 URL 构造依赖 alicdn 命名规律，若平台改规则，下载会失败，截图兜底要保留。
- 图片下载禁用了代理直连 alicdn，若网络环境变化，可能需要调整。
- 主图保存路径按 item_id 命名，聚合商品多张图共用，符合去重设计。
