# 模块经验沉淀：12 结果回填与复核

## 1. 模块目标

把每个商品的时间、价格、权益回填到本地链接库副本，保留原格式，输出本地 Excel；同时收集时间、价格、权益里拿不准或缺失的项，生成人工复核清单。

## 2. 实际产出

- core/excel_writer.py：加载链接库副本，按行回填 F 到 K 列，长文本自动换行，另存带时间戳的结果文件
- core/review.py：ReviewCollector 扫描已处理结果，生成复核项和 Markdown 清单
- 真机验证：美的 631 白灰两行都填 4349，海尔 617 白 4999 灰 4899，时间权益正确
- 复核清单在两个商品上只报 1 项，是美的 631 时间省略月份

## 3. 遇到的问题

- 验证脚本里 Path 和字符串格式化的运算符优先级出错，加括号解决。
- 复核清单一开始把没处理的商品都算成“未采集”，冒烟时噪声很大，改成只检查已处理结果。

## 4. 踩过的坑

- `path / "%s" % x` 会先算 `%`，要写成 `path / ("%s" % x)`。
- 回填要在链接库副本上写，不能覆盖原文件，也不能新建空表导致原格式丢失。
- 多价格回填按行的 color_group 取，不能所有行填同一个。

## 5. 原本以为 vs 实际发现

- 以为回填要处理很多格式，实际加载原工作簿再写值，格式自然保留，只补换行对齐。
- 以为复核逻辑很复杂，实际围绕 need_review 和空值就能覆盖主要场景。
- 复核清单不应该靠“结果缺失”推断失败，失败要由 pipeline 显式记录。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- pipeline 批量结束后会调用 ExcelWriter.write 和 ReviewCollector，签名要稳定。
- 结果文件带时间戳，断点续跑时要注意不要把结果分散到多个文件。
- 权益单元格用换行连接，行高和列宽影响阅读，冒烟时在 Excel 里核对。
- 价格回填成“待确认”的情况，要和复核清单对得上。
- 复核清单目前不含权益拿不准项，后续若 benefit 加标记，要同步接入。
