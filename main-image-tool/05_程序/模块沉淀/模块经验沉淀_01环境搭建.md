# 模块经验沉淀：01 环境搭建

## 1. 模块目标

搭建 05_程序 项目骨架，固化依赖清单，验证 playwright、rapidocr、openpyxl、PyYAML、Pillow 等核心库可正常导入，RapidOCR 可成功初始化。

## 2. 实际产出

- 目录：05_程序/config、05_程序/core、06_结果输出
- requirements.txt：playwright、rapidocr-onnxruntime、openpyxl、PyYAML、Pillow 五个直接依赖及版本下限
- 新安装 rapidocr-onnxruntime 1.4.4，连带 onnxruntime 1.23.2、opencv-python 5.0.0.93、Shapely 2.1.2、pyclipper 1.4.0
- 验证结果：python 3.10.11，全部库 import 通过，RapidOCR 初始化成功

## 3. 遇到的问题

- pip install 超过前台等待时间被自动转到后台，需要用任务轮询方式等它装完，不影响结果。

## 4. 踩过的坑

- 本模块没有明显的坑，安装一次通过。

## 5. 原本以为 vs 实际发现

- 以为要装全套依赖，实际当前全局环境里 playwright、openpyxl、PyYAML、Pillow、numpy 都已装好（参考项目和前期验证遗留），只缺 rapidocr。
- 担心 rapidocr 与 numpy 2.x 不兼容，实际 1.4.4 明确支持 numpy 1.19 到 3.0，初始化正常。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 所有 core 模块都建立在这些库之上，环境一旦变化会影响全部下游。
- opencv 装到了 5.0.0.93，版本较新，rapidocr 内部若用到旧版 cv2 接口，可能在真实识别时报警，需要在 OCR 真机跑图时验证。
- 当前用的是全局 Python 环境，多个项目共用，依赖版本可能被其他项目改动；换机或重建环境时必须以 requirements.txt 为准。
- CDP 连接方式不依赖 playwright 下载浏览器内核，但步骤 3 真机连接时仍要确认浏览器和端口状态。
