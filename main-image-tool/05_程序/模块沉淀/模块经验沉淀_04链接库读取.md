# 模块经验沉淀：04 链接库读取

## 1. 模块目标

读取本地链接库 Excel，解析门体、品牌、简称、链接、颜色，识别商品 id 并做聚合，为后续采集提供去重后的任务清单，同时把颜色归并到白、灰两大类。

## 2. 实际产出

- core/link_library.py：ProductItem 数据结构、颜色归并函数、LinkLibrary 读取与聚合
- 读取结果：68 行，47 个唯一商品，17 个聚合商品
- 颜色归并：白 31、灰 33、待确认 4
- 风控参数：config 里新增每 10 个商品长休息、同 id 只打开一次等开关
- 验证：按唯一 id 采集，相比逐行打开减少 21 次跳转

## 3. 遇到的问题

- 探查脚本第一次运行没有输出，重跑后正常，属于偶发。
- 颜色列有 35 种写法，比预想的多，需要靠关键词和映射表归并。

## 4. 踩过的坑

- 商品 id 要从链接的 id 参数里提取，不能用行号或简称当唯一标识，否则无法识别同一商品的多行。
- 待确认颜色的判断要放在关键词匹配之前，避免个别颜色误命中。

## 5. 原本以为 vs 实际发现

- 以为 68 行要打开 68 次页面，实际只有 47 个唯一商品，同一商品按颜色或门型拆了多行，打开一次就能识别再回填。
- 以为聚合只按颜色拆，实际还有按门型拆（十字、法式），甚至同一商品在不同店铺有 4 行。
- 发现“冰晶拉丝”这类不带颜色字的名称，关键词匹配不到，自动落到待确认。

## 6. 下游引用及后续开发可能影响该模块的风险检点

- 采集和回填都依赖 item_id 聚合，提取结果要能按行号回填到同一 id 的多个行。
- 去重打开是风控的关键，若后续为了省事改成逐行打开，会增加 21 次跳转，风险明显上升。
- 颜色归并结果直接影响价格对应，待确认的 4 个颜色（山海米、云雾岩、冰晶拉丝、烟青色）等用户拍板后要更新规则。
- 链接库若更新增删行，要重新 load，行号变化会影响回填位置。
- 频率控制参数（长休息、商品间隔）在 pipeline 里要真正用上，不能只配置不执行。

## 7. 待办

- 已确认口径：单一价格不区分颜色直接填，4 个待确认颜色都是单一价格，无需再确认归属；颜色归并只在多价格场景使用。
- 步骤 13 编排时落实按唯一 id 打开、分批长休息的频率控制。
- 链接库更新后重新读取并核对行数。
